# System-Design Learning Notes

Study the system as a local protocol workbench and scenario runner: protocol packs, collections, environments, secret references, target fixtures, isolated execution, event capture, redaction, verification, and reproducible reports.

For every component, document its problem, inputs/outputs, owned state, failure behavior, scaling model, consistency needs, trust boundary, observability, audit behavior, and rejected alternatives. Compare scenario-runner options against isolation strength, portability, resource cost, local developer experience, and reset guarantees.

Identity concepts such as credentials, claims, sessions, tokens, directories, and policies are learned through protocol packs and synthetic targets; they are not a mandate to build a shared IAM engine.
